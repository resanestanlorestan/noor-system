# گزارش مشاوره — راستی‌آزمایی سه درخواست (آبان ۱۴۰۵)

بررسیِ فقط‌خواندنی روی کد نسخهٔ ۲.۱۴.۱ (کامیت 8d95817) برای سه درخواست مدیریتی: پیامک وضعیت بررسی پرونده، تکمیل خروجی اکسل، و رفع خطای کد ملی تکراری پس از حذف پرونده.

## ۱) پیامک وضعیت بررسی پرونده — ✅ انجام‌شده (از الحاقیهٔ ۲.۱۲.۰)

| نیازمندی | وضعیت | شواهد کد |
| --- | --- | --- |
| پیامک «تأیید اطلاعات» پس از بررسی | ✅ | قالب `case_approved` — ارسال در اکشن بررسی `src/app/actions/cases.ts` |
| پیامک «نیازمند اصلاح» | ✅ | قالب `case_correction` با وضعیت `needs_correction` |
| ثبت توضیحات کارشناس درباره علت اصلاح | ✅ | یادداشت کارشناس الزامی (حداقل ۵ نویسه) + فهرست مدارک درخواستی، هر دو در متن پیامک (سقف ۱۶۰ نویسه) و در جدول `correction_requests` |
| پیامک رد پرونده | ✅ | قالب `case_rejected` با الزام ثبت دلیل |
| قابل‌ویرایش بودن متن پیامک‌ها | ✅ | هر سه قالب از پنل مدیریت پیامک‌ها (کategorie «case») قابل ویرایش‌اند |
| پیامک «ارسال برای بررسی» به کارشناس‌ها | ✅ | قالب `case_submitted` |
| ثبت در صندوق پیام با دسته و کلید قالب | ✅ | `notifyUsers` → `queueSms` با `smsCategory` و `smsTemplateKey` |
| آزمون | ✅ | `tests/case-release-212.test.ts` — وجود قالب‌ها و رندر متن با توضیح کارشناس |

**شکاف باقی‌مانده (پیشنهاد اصلاح در نسخهٔ بعد):** پیامک نتیجهٔ بررسی فقط به گیرنده‌ای می‌رسد که «حساب کاربری با شمارهٔ همراه» دارد (`notifyUsers` شماره را از جدول `users` می‌گیرد). برای پرونده‌های قدیمی یا کارشناسی‌ثبت‌شده‌ای که فعالِ آن‌ها حساب کاربری ندارد (`activist.userId = null`)، پیامک نتیجه ارسال نمی‌شود. راه‌حل پیشنهادی: در نبود حساب، ارسال با شمارهٔ خودِ فعال (`activists.phone`) به‌عنوان جایگزین.

**نکتهٔ عملیاتی:** ارسال واقعی پیامک نیازمند تنظیم پنل پیامکی (پیامک‌پنل یا کاوه‌نگار) در تنظیمات است؛ در نبود آن، پیام‌ها در صندوق محلی سامانه ثبت می‌شوند.

## ۲) تکمیل خروجی اکسل — ✅ انجام‌شده (از الحاقیهٔ ۲.۱۲.۰) با دو نکتهٔ تصمیم‌گیری

خروجی `/api/cases/export` شامل شیت «فهرست پرونده‌ها» + شیت «اطلاعات کامل» (۳۷ ستون برای هر پرونده) + ۶ شیت تفصیلی (یک ردیف به‌ازای هر رکورد):

| مورد درخواستی | وضعیت | محل در خروجی |
| --- | --- | --- |
| اطلاعات هویتی | ✅ | «اطلاعات کامل» — نام، نام پدر، شناسنامه، محل صدور، تولد، جنسیت، تماس‌ها، ایمیل، آدرس‌ها |
| تحصیلات دانشگاهی و حوزوی | ✅ | ستون‌های تجمیعی + شیت «تحصیلات» رکوردبه‌رکورد (از ۲.۱۴.۱ شامل کارت‌های گام هویتی) |
| میزان حفظ قرآن | ✅ | ستون «میزان حفظ» + «نوع مدرک حفظ» |
| مدارک عمومی و تخصصی | ✅ | شیت «مدارک بارگذاری‌شده» با نوع مدرک + تعداد مدارک هر پرونده |
| رشته‌های معلمی و مدرسی | ✅ | داخل ستون «تخصص‌ها و جزئیات» (جزئیات هر تخصص با `formatSpecialtyDetail`) — بدون ستون مستقل |
| فعالیت‌های قرآنی | ✅ | ستون تجمیعی + شیت اختصاصی (تدریس، داوری، مسابقات، پژوهش) |
| تخصص‌ها (چندانتخابی) | ✅ | همهٔ گزینه‌های انتخاب‌شده با جداکننده « \| » |
| سوابق کاری و همکاری | ✅ | ستون تجمیعی + شیت «سوابق همکاری» با نوع همکاری |
| دوره‌های گذرانده‌شده | ✅ | ستون تجمیعی + شیت «دوره‌ها» |
| وضعیت بررسی / تأیید / نیازمند اصلاح | ✅ | ستون «وضعیت بررسی پرونده» در هر دو شیت + تاریخ ارسال برای بررسی |
| آثار مؤلف و گواهینامه‌ها | ✅ | شیت «آثار و گواهینامه‌ها» |

**دو نکتهٔ نیازمند تصمیم مدیر:**
1. **کد ملی در خروجی فقط ۴ رقم آخر است** (سیاست حفاظت داده: `••••••۱۲۳۴`). اگر «هیچ اطلاعاتی نباید حذف شود» شامل کد ملی کامل برای مدیران می‌شود، اصلاح کوچکی لازم است.
2. **رشته معلمی/مدرسی ستون مستقل ندارد** و داخل ستون تخصص‌ها می‌آید؛ در صورت نیاز به ستون مجزا، افزوده‌شدنش ساده است.

## ۳) رفع خطای کد ملی تکراری پس از حذف پرونده — ✅ انجام‌شده و ریشه‌ای (از الحاقیهٔ ۲.۱۲.۰)

| نقطهٔ بررسی خواسته‌شده | یافته |
| --- | --- |
| رکوردهای حذف‌شده در دیتابیس | حذف نرم است؛ فقط `deleted_at` ست می‌شود و داده‌ها باقی می‌مانند (`src/app/actions/cases.ts`) |
| منطق اعتبارسنجی کد ملی | هشدار تکراری‌بودن فقط رکوردهای زنده را می‌بیند (`isNull(activists.deletedAt)` در `case-steps.ts`) |
| حذف نرم (Soft Delete) | پایهٔ طراحی است و دست‌نخورده حفظ شده |
| محدودیت Unique در پایگاه داده | **ریشهٔ مشکل و راه‌حل:** ایندکس یکتای کامل به ایندکس پارشیال `activists_national_id_active_unique` با شرط `deleted_at IS NULL AND national_id_hash IS NOT NULL` تغییر کرده (`src/db/schema.ts` و مایگریشن `drizzle/0019_release-2120.sql`) — یکتایی فقط میان رکوردهای زنده اعمال می‌شود |

**نتیجه (با آزمون دیتابیسی در `tests/case-release-212-flow.test.ts`):** پس از حذف پرونده، ثبت مجدد با همان کد ملی موفق است؛ برای پرونده‌های فعال، دو ردیف زنده با یک کد ملی در سطح دیتابیس مسدود است (خطای ۲۳۵۰۵)؛ احیای رکورد حذف‌شده‌ای که باعث دو ردیف زنده شود هم مسدود است؛ اطلاعات پرونده‌های فعال آسیب نمی‌بیند. مایگریشن ۰۰۱۹ در استقرار ۲.۱۲.۰ روی تولید اجرا شده است.

## جمع‌بندی

- مورد ۱ (پیامک وضعیت بررسی): **انجام‌شده**؛ فقط پوشش فعالِ بدون حساب کاربری به‌عنوان بهبود پیشنهادی باقی است.
- مورد ۱۲ (خروجی اکسل): **انجام‌شده**؛ دو تصمیم اختیاری — کد ملی کامل مدیران و ستون مستقل معلمی/مدرسی.
- مورد ۱۳ (کد ملی تکراری پس از حذف): **انجام‌شده و ریشه‌ای** با آزمون پوشش داده‌شده.
